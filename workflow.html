🧑‍💻 2. ฝั่งพนักงาน (User Workflow)

1

ตรวจสอบสถานะ (Search)

พนักงานสแกน QR Code หรือเข้าเว็บ กรอกเบอร์โทรหรือรหัสพนักงานเพื่อดูสถานะเครื่องของตัวเอง

status: pending
2

จองคิว (Appointment)

หาก IT ทำเครื่องเสร็จแล้ว พนักงานจะเห็นปุ่ม "นัดหมายรับเครื่อง" และสามารถเลือกวัน/เวลาที่สะดวกได้ (ระบบจะเช็คโควต้าคิวว่าเต็มหรือยัง)

status: completed
3

ยืนยันและรับเครื่อง (Done)

พนักงานได้รับใบยืนยันคิวบนหน้าจอ และนำไปโชว์ให้ IT ดูเพื่อรับเครื่องตามวันและเวลาที่จองไว้

status: scheduled
sequenceDiagram actor User as พนักงาน (User) participant UI as หน้าเว็บ (index/appointment) participant DB as ฐานข้อมูล User->>UI: ค้นหาด้วยรหัส/เบอร์ UI->>DB: Query ข้อมูล DB-->>UI: คืนค่าสถานะปัจจุบัน alt สถานะ = completed UI-->>User: แสดงปุ่ม "นัดหมายรับเครื่อง" User->>UI: เลือกวัน/เวลา UI->>DB: เช็ค slot_limits ว่าคิวเต็มไหม? DB-->>UI: ไม่เต็ม UI->>DB: อัปเดต status เป็น scheduled UI-->>User: แสดงหน้ายืนยันนัดหมายสำเร็จ else สถานะ = pending UI-->>User: แสดงข้อความ "อยู่ระหว่างดำเนินการ" end

👨‍🔧 3. ฝั่งเจ้าหน้าที่ไอที (Admin / Dashboard Workflow)

1

ตั้งค่าคิว (Settings)

แอดมินกำหนดวันและเวลาที่สามารถมารับเครื่องได้ พร้อมใส่ "จำกัดจำนวนคิว (Slot Limits)" ของแต่ละรอบเวลา

2

เตรียมเครื่อง (In Progress)

แอดมินดูรายชื่อในแท็บ "รอดำเนินการ" เมื่อ Backup และเตรียมเครื่องเสร็จ กดปุ่ม "เสร็จแล้ว"

3

ตรวจสอบคิว (Calendar)

แอดมินดูรายชื่อพนักงานที่นัดหมายไว้ผ่าน "ปฏิทิน" หรือแท็บ "นัดหมายแล้ว" เพื่อจัดเตรียมเครื่องให้ตรงเวลา

4

ส่งมอบ (Delivered)

เมื่อพนักงานมารับเครื่อง แอดมินกดปุ่ม "คืนงานเสร็จ" เพื่อปิด Job งานอย่างสมบูรณ์
